# Assegai ORM 0.10.2 Release Notes

Assegai ORM 0.10.2 adds deterministic, opt-in entity hydration to repository and `EntityManager` reads.

## Highlights

- Pass `hydrate: true` to return root rows as instances of the requested entity class.
- Explicitly requested relations are hydrated into their declared target entity classes.
- Column aliases are mapped back to entity property names.
- Backed enums, `DateTime`, and booleans use the ORM's existing type-conversion pipeline.
- Default and caller-controlled exclusions are applied after hydration, so sensitive properties remain protected unless deliberately requested.
- Existing fetch behavior remains the default for compatibility.

## Usage

```php
$user = $users->findOne([
    'where' => ['email' => $email],
    'relations' => ['profile'],
    'hydrate' => true,
])->getData();
```

When a row is found, `$user` is a `UserEntity` and `$user->profile` is a `ProfileEntity`. Typed properties receive converted values rather than database scalars.

The option is available through `find()`, `findOne()`, `findBy()`, `findAndCount()`, and `findAndCountBy()` on repositories and `EntityManager`.

## Compatibility and security

No entity or database migration is required. Calls that do not pass `hydrate: true` preserve their existing result shape.

Hydration does not bypass read exclusions. Sensitive properties are excluded by default, and an explicit `exclude` list remains authoritative. Trusted authentication code can combine `hydrate: true` with `exclude: []` when it intentionally needs access to a credential field; the returned entity must not be serialized into a public response.

## Additional correctness fixes

- Hydrated reads no longer depend on a datasource-wide PDO fetch class, avoiding driver-level assignment failures for enum and date properties.
- Count results are handled consistently for associative and object PDO fetch modes.
- `findAndCount()` and `findAndCountBy()` now retain their result rows while reporting the matching total.

## Verification

- Multi-entity and legacy single-fetch-class datasource coverage
- Root alias, backed-enum, `DateTime`, and boolean conversion
- Repository and `EntityManager` read entry points
- One-to-one, many-to-one, one-to-many, and many-to-many relation hydration
- Sensitive and explicit exclusion behavior after hydration
- PHPUnit and SQLite integration suites
